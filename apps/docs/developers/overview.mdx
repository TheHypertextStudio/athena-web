## Which one do I want?

| You are building | Use |
| --- | --- |
| An AI agent that works in Docket | [MCP](/developers/connect-an-agent-mcp) |
| A script that syncs something nightly | [REST](/developers/rest-api) |
| A product other Docket users install | [OAuth app](/developers/authentication) + MCP or REST |
| An integration that reacts to changes | REST plus the [SSE stream](/developers/rest-api#live-updates) |

The MCP surface covers the most ground, because it serves callers that describe intent. `capture`
turns a sentence into a task. `organize` takes an entire plan in one call and reconciles it, so a
re-run creates no duplicates.

## The model in one screen

Everything is scoped to an **Organization**, which is a workspace and the tenant boundary. Inside
one:

```
Organization
  ├─ Team          owns workflow states, cycles, and a triage queue
  ├─ Initiative    a theme; holds no work; many-to-many with the two below
  ├─ Program       ongoing operations; holds Projects and Tasks
  ├─ Project       a bounded effort; holds Tasks; carries Milestones
  └─ Task          the atomic unit; subtasks, acyclic dependencies, attachments, labels
```

Three more concepts sit alongside that hierarchy:

- **Cycles** are a team's recurring time window. They schedule Tasks without containing them.
- **Updates** are narrative status, and they drive health.
- **Comments** are threaded, and they attach to anything.

Docket keeps two kinds of relationship apart:

| Kind | What it is |
| --- | --- |
| **Containment** | A hard parent-to-child edge. Authorization cascades down it. |
| **Association** | A soft link either side can live without. An Initiative themes a Project, a Cycle schedules a Task, a Task blocks a Task. |

The [user-facing concept guides](/guides/concepts/terminology) describe the same model in product
terms. Start there if any of the above is unfamiliar.

<Note>
  Workspaces relabel these words for their members, so a Cycle may display as a Season or a Sprint.
  **The API always uses the default names**, so `cycle` is `cycle` regardless of what the UI shows.
  See [Terminology](/guides/concepts/terminology).
</Note>

## Conventions every surface shares

| | |
| --- | --- |
| **Identifiers** | ULIDs. Sortable and opaque. Never parse them. |
| **Pagination** | Keyset, via an opaque cursor. Never offset. |
| **Errors** | RFC 9457 problem documents, with a stable machine-readable `code`. See [Errors](/developers/errors). |
| **Idempotency** | Unsafe operations accept an `Idempotency-Key` header. |
| **Authorization** | The capability ladder `view < comment < contribute < assign < manage`, cascading down containment. A token can never exceed the person who granted it. |

## What a token can do

**A token never grants more than the human behind it has.** OAuth scopes are the first gate, and
the person's own roles and grants in each workspace stay binding underneath. A read-only token
calling a write tool gets a `403` with an `insufficient_scope` challenge, and well-behaved clients
step up automatically.
