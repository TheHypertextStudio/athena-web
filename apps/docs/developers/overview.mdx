Docket exposes work through an MCP server and a prerelease REST contract. Both run as the person
who authorizes the client. The authorization scope narrows that person's access. It never expands
it.

<Warning>
  The public API is prerelease. Docket publishes one current compatibility contract, `0.1.0`. It
  does not publish an SDK or send outbound webhooks.
</Warning>

## Choose an interface

| You are building                                     | Use                                                                  |
| ---------------------------------------------------- | -------------------------------------------------------------------- |
| An agent that understands work in natural language   | [MCP](/developers/connect-an-agent-mcp)                              |
| A client that needs the current REST canary          | [REST](/developers/rest-api) and [OAuth](/developers/authentication) |
| A client that needs task, project, or time mutations | MCP until those REST operations publish OAuth access contracts       |

The current REST bearer canary is deliberately narrow: `GET /v1/orgs` and `HEAD /v1/orgs` accept
an OAuth token with `work:read`. Other business REST operations remain first-party session routes
until their published operation contracts expand this boundary.

## The work model

An Organization is Docket's tenant boundary. Teams carry workflow states. Tasks can belong to
projects, programs, or initiatives, and a task's `parentTaskId` creates a task hierarchy. Personal
Athena data belongs under `/v1/me/athena`, not an organization work route.

Use names only where a documented MCP tool accepts them. REST identifiers and fields come from the
live [OpenAPI reference](https://api.clearthedocket.com/v1/docs).

## Build against the contract

Send `Docket-Version: 0.1.0` when a client needs to assert the current contract. Every public REST
response identifies the contract and its deployed revision. Read [API versions](/developers/api-versions)
before pinning client behavior, and read [Errors](/developers/errors) before writing retries.
