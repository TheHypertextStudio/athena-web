The REST resource identifier is `https://api.clearthedocket.com/v1`. The live reference is
[`/v1/docs`](https://api.clearthedocket.com/v1/docs), and its OpenAPI document is
[`/v1/openapi.json`](https://api.clearthedocket.com/v1/openapi.json).

<Warning>
  `0.1.0` is prerelease and Docket supports one current compatibility contract. Docket does not
  publish an SDK, retain older public contracts, or send outbound webhooks.
</Warning>

## Authentication boundary

`GET /v1/config` is public. The current OAuth bearer boundary is only `GET /v1/orgs` and
`HEAD /v1/orgs`, which require `work:read`. The REST access policy treats every business operation
outside that explicit boundary as session-only. Do not infer bearer access from an endpoint's
presence in OpenAPI.

```http
Authorization: Bearer <access-token>
Docket-Version: 0.1.0
```

Use [Authentication](/developers/authentication) to discover the resource and authorization server.
Use [Make your first request](/developers/make-your-first-request) for the working organization-list
flow.

## Contract headers

Each public REST response carries `Docket-Version` and `Docket-Revision`. The version identifies
the compatibility contract. The revision identifies the deployed source revision. Send no version
header, or send the exact current version. Docket rejects another version with
`unsupported_api_version`.

Read [API versions](/developers/api-versions) and [API release notes](/developers/api-release-notes)
before deciding how a client should react to a contract change.

## Errors

Failures use RFC 9457 problem documents. Branch on the stable `code`, not a human-readable title
or detail. The live reference owns request and response schemas. The error page explains retry and
reauthorization behavior.
