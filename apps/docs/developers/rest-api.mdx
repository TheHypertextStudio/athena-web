## Authentication

Send a bearer token on every request:

```http
Authorization: Bearer <token>
```

**Only `GET /v1/config` works without one.** See [Authentication](/developers/authentication) to
get one.

## Conventions

<AccordionGroup>
  <Accordion title="Identifiers are ULIDs" defaultOpen>
    26 Crockford base-32 characters, matching `^[0-9A-HJKMNP-TV-Z]{26}$`.

    IDs are branded per entity type: a `TaskId` fails where a `ProjectId` belongs. Never parse
    one.
  </Accordion>
  <Accordion title="Pagination is keyset, never offset">
    Pass `cursor` and `limit`. Read `nextCursor`; it is `null` on the last page.

    ```http
    GET /v1/orgs/{orgId}/tasks?limit=50&cursor=<opaque>
    ```
  </Accordion>
  <Accordion title="Errors are RFC 9457 problem documents">
    `application/problem+json`, carrying a `code` such as `dependency_cycle`, an HTTP `status`, and
    per-field `fieldErrors`.

    **Branch on `code`.** See [Errors](/developers/errors).
  </Accordion>
  <Accordion title="Any POST accepts an Idempotency-Key">
    ```http
    Idempotency-Key: <your-unique-key>
    ```

    Docket dedupes per user for 24 hours. A replay returns the recorded response with
    `Idempotency-Replayed: true`. Send the same key with a different body and you get
    `422 idempotency_key_reuse`.
  </Accordion>
  <Accordion title="Use ETags to make writes conditional">
    Every `GET` returns a strong `ETag`. Send it back as `If-None-Match` and an unchanged resource
    answers `304`.

    Send it as `If-Match` on a write and Docket rejects the write with `412` if someone changed the
    resource since you read it. Re-read and retry. Omit the header and the write is
    last-writer-wins.
  </Accordion>
  <Accordion title="Creates answer 201, queued work answers 202">
    A create returns `201` with a `Location` naming the new resource. Work that Docket queues
    rather than finishes returns `202` with the `Location` of a status monitor.
  </Accordion>
  <Accordion title="Declare a Content-Type Docket reads">
    Send `application/json`, or a form encoding where a file belongs. Anything else answers `415`
    with an `Accept` header naming what would work. An `Accept` header that excludes JSON answers
    `406`.
  </Accordion>
  <Accordion title="Responses are private and revalidated">
    Docket answers `private, no-cache` and varies on your credentials. Store a response, then
    revalidate it against its `ETag` before reuse.
  </Accordion>
  <Accordion title="Request and response bodies share one schema">
    Docket validates both against the schemas `/v1/docs` renders. A response that does not match
    is a bug.
  </Accordion>
</AccordionGroup>

## Permissions

**Membership.** Every `/v1/orgs/{orgId}/*` route needs an active Actor. Non-members get **404**,
never 403. Probing tells you nothing.

**Capability.** Mutations need a capability on the ladder:

```
view  <  comment  <  contribute  <  assign  <  manage
```

Reassign a task, you need `assign`. Post a comment, `comment`. Rename the workspace, `manage`. Read
endpoints push the predicate into the query. Skip the client-side filter. Agents pass the
identical checks, plus the [approval gate](/guides/athena/proposals-and-approvals).

## Cross-workspace surfaces

The Hub (`/hub/today`, `/portfolio`, `/search`, `/inbox`, `/activity`), notifications, and the
personal daily plan span tenants. Docket fans them out as **one permission-scoped query per
membership** and merges in application code. No SQL join crosses tenants.

## Live updates

Hold `GET /v1/stream/sse` open for `stream-event` frames, pinged every 25 seconds. Cannot hold a
connection? Poll `/v1/hub/stream` and `/v1/orgs/{orgId}/stream`.

<Warning>
  Docket sends **no outbound webhooks**. To react to changes, poll a stream endpoint or subscribe
  over [MCP](/developers/mcp-tools-and-resources#subscriptions).
</Warning>

## REST or MCP?

The [MCP server](/developers/connect-an-agent-mcp) calls the identical service layer beneath the
same permission engine. Use REST when you know which record you want and which fields to set. Use
MCP when your caller describes intent: tools take names anywhere IDs go, and `organize` applies a
whole plan in one call.
