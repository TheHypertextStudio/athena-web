## Program: work that never finishes

Support tickets keep arriving. Books keep needing to be current. The tutoring program runs every
term. Put that work in a Program.

**A Program holds work directly.** "After-School Program" holds the project "Fall term enrolment"
and recurring Tasks that belong to no project.

Read a Program by its **health and flow**. "62% complete" tells you nothing about bookkeeping.

### Programs can end

Wind down the after-school program at the end of its last term. The seeded program statuses are
`Proposed · Active · Paused · Completed · Archived`, where `Archived` means retired and kept for
history. Your workspace defines its own set: delete `Completed` if your programs only ever end by
being archived. See [Labels and statuses](/guides/concepts/labels-and-statuses).

## Initiative: a theme that holds no work

Create the Initiative "Grow revenue" to say why the pricing project and the website rebuild belong
together. Nobody works on "Grow revenue" itself.

**Initiatives hold no work.** Associate Programs and Projects with them, many-to-many. "Website
rebuild" can serve "Grow revenue" and "Expand to a second city" at the same time, and neither owns
it.

An Initiative reports health rolled up from everything under it.

### Nesting depth

Change the maximum depth in **Settings → Work structure**. Point a nesting link at an Initiative in
another workspace and it records the relationship, granting no access to what it points at.

## Project, Program, Initiative, or Task

| The work | The shape |
| --- | --- |
| Has an outcome and a finish line | [Project](/guides/concepts/projects) |
| Keeps going, and holds real work | Program |
| Is a reason several efforts belong together | Initiative |
| Is one thing a person does | [Task](/guides/concepts/tasks) |

<Tip>
  Stuck between a Program and an Initiative? Ask whether tasks would ever sit directly inside it.
  If yes, use a Program.
</Tip>
