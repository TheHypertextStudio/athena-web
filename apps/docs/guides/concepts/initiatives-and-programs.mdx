## Program: work that never finishes

Support tickets arrive every day. The books need to be current every month. The tutoring program
runs every term. Put that work in a Program.

**Put work directly in a Program.** "After-School Program" includes the project "Fall term
enrolment" and recurring Tasks with no project.

Read a Program by its **health and its updates**. "62% complete" tells you nothing about
bookkeeping.

### Programs can end

Wind down the after-school program at the end of its last term. The seeded program statuses are
`Proposed · Active · Paused · Completed · Archived`, where `Archived` means retired and stored for
history. Your workspace defines its own set: delete `Completed` if your programs only ever end by
being archived. See [Labels and statuses](/guides/concepts/labels-and-statuses).

## Initiative: a theme with no work of its own

Create the Initiative "Grow revenue" to say why the pricing project and the website rebuild are
related. Nobody works on "Grow revenue" itself.

**You never add work to an Initiative.** Link as many Programs and Projects to an Initiative as you
want, and link one Project to several Initiatives. "Website rebuild" can link to "Grow revenue" and
"Expand to a second city" at the same time, and neither owns it.

An Initiative reports health rolled up from everything under it.

### Nesting depth

Change the maximum depth in **Settings → Work structure**. Point a nesting link at an Initiative in
another workspace and it records the relationship, granting no access to what it points at.

## Project, Program, Initiative, or Task

| The work | The shape |
| --- | --- |
| Has an outcome and a finish line | [Project](/guides/concepts/projects) |
| Never finishes, and includes real work | Program |
| Explains why several efforts are related | Initiative |
| Is one thing a person does | [Task](/guides/concepts/tasks) |

<Tip>
  Stuck between a Program and an Initiative? Ask whether you would ever add tasks directly to it.
  If yes, use a Program.
</Tip>
