---
title: 'Projects'
description: 'Organize work that has an outcome and a finish line.'
---

Use a Project for work that ends when an outcome ships. Put ongoing work in a
[Program](/guides/concepts/programs).

## Set the Project properties

| Property     | What it controls                                              |
| ------------ | ------------------------------------------------------------- |
| **Lead**     | The person or agent accountable for the Project.              |
| **Team**     | The Team that owns the Project.                               |
| **Status**   | One state from the workspace's Project workflow.              |
| **Health**   | On track, at risk, or off track.                              |
| **Priority** | The Project's relative importance.                            |
| **Start**    | A precise day or a broader planning period.                   |
| **Target**   | A precise day or a broader planning period.                   |
| **Program**  | The ongoing area that contains the Project, when one applies. |

A Project can contain milestones, Tasks, resources, updates, and threaded discussion.

## Plan at the level you know

Choose a precise day when the date is firm. Choose a month, quarter, half-year, or year when that is
all you know. Docket uses the workspace's fiscal year for broad quarters, half-years, and years.

Changing the fiscal-year start under **Settings → Work structure** affects new broad dates. An
existing broad date keeps the fiscal calendar that was in effect when someone selected it.

## Use milestones for checkpoints

Add a Milestone when people need to plan around a checkpoint inside the Project. A Milestone has a
date and belongs to one Project. It is not a substitute for the Project's target.

See [Cycles](/guides/concepts/cycles) and [Milestones](/guides/concepts/milestones) for the
difference between a workspace planning period and a Project checkpoint.

## Link dependencies

Make one Project depend on another when the first cannot finish before the second. Use the Project
dependency view to inspect and edit those links. Docket rejects loops.

## Connect the Project to larger work

Put the Project in one Program when it belongs to an ongoing area. Link it to one or more
Initiatives to show why the outcome matters. The Program contains the Project. Initiatives do not.

## Start from a template

Save a template when Projects begin with the same structure. Create the next Project with **Start
from template**, then change the copied details for the new work. Manage templates under
**Settings → Templates**.

## Publish a brief

An admin can publish a read-only Project brief for people who do not have a Docket account. Manage
the public address and publishing controls under **Settings → Publishing**.
