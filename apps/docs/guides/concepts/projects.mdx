---
title: "Projects"
description: "A bounded effort with an outcome that you finish and close."
---

A Project is a bounded body of work with an outcome and often a deadline. "Launch v2."
"Spring Gala." "Rebuild the donor page." You finish it, and then it closes.

Work that continues after each deliverable inside it lands belongs in a
[Program](/guides/concepts/initiatives-and-programs).

## What a project carries

| Field | What it holds |
| --- | --- |
| **Lead** | The Actor accountable for the project. |
| **Dates** | A start and a target. Either one can be left empty. |
| **Status** | One of the workspace's own project statuses. |
| **Health** | `on_track`, `at_risk`, or `off_track`, set by the [updates](/guides/concepts/updates-and-health) posted on the project. |
| **Contents** | Milestones, Tasks, attachments, and threaded discussion. |

A project also reports **weighted progress**. A reader sees how much of the work is done and how
the work is going without opening the project.

## Milestones

A Milestone is an attribute of a Project. It is a dated checkpoint that groups some of the
project's tasks toward a deliverable: "Beta to design partners", "Invitations mailed".

Add milestones when a project has real internal checkpoints. A project with no milestones is
completely ordinary. See [Cycles and milestones](/guides/concepts/cycles-and-milestones).

## Where a project sits

A Project can sit directly inside the workspace, or inside a Program when it is one bounded push
within a continuous area of operations.

```
Workspace
  ├─ Program "After-School Program"
  │    └─ Project "Fall term enrolment"
  └─ Project "Website rebuild"
```

Any number of [Initiatives](/guides/concepts/initiatives-and-programs) can also *theme* a project.
Theming is an association: an initiative gathers projects under a shared strategic theme without
containing them, and one project can carry several themes at once.

## Dependencies and resources

A project can **depend on** another project, which records the delivery order when two bounded
efforts run in sequence.

A project also holds **resources**: links, documents, and references to items in connected tools.
The material a project runs on sits beside the work.

## Publishing a project

You can publish a project as a **brief**: a read-only public page at a web address you control,
for people who need to see where something stands without an account.

An admin configures the address under **Settings → Publishing**. A workspace can point a custom
domain at its briefs.

## Templates

Save a template when you create the same kind of project repeatedly, such as every client
engagement or every event. A template is a named, reusable pre-filled draft, scoped to you, a
Team, or the whole workspace.

Manage templates in **Settings → Templates**.

<Note>
  Tasks, Projects, Initiatives, and Programs are all templatable. Cycles and Teams are not: a
  Cycle is a span of time and a Team is a group of people, so neither has a document to seed.
</Note>
