title: "Terminology"
description: "Why the words in these docs may differ from the words on your screen, and how to translate between them."

These docs call the six units of work **Initiative**, **Program**, **Project**, **Task**,
**Cycle**, and **Team**. Your workspace may show different words for the same six things.

That is a setting. Each workspace picks a **terminology preset**, and the preset relabels the
work hierarchy to language that fits the kind of organization you run. The data model underneath
is identical in every case — a Cycle called a Season is the same object with the same behaviour,
wearing a different label.

## The three presets

<Tabs>
  <Tab title="Startup">
    The default, and the language these docs are written in.

    | Concept in these docs | Shown in your workspace |
    | --- | --- |
    | Initiative | Initiative |
    | Program | Program |
    | Project | Project |
    | Task | Task |
    | Cycle | Cycle |
    | Team | Team |
  </Tab>
  <Tab title="Nonprofit">
    Mission-oriented labels, where the ongoing program is the hero term and work is planned in
    seasons.

    | Concept in these docs | Shown in your workspace |
    | --- | --- |
    | Initiative | **Campaign** |
    | Program | Program |
    | Project | Project |
    | Task | Task |
    | Cycle | **Season** |
    | Team | **Chapter** |
  </Tab>
  <Tab title="Agency">
    Client-services labels, where an ongoing relationship is a retainer and a body of client work
    is an engagement.

    | Concept in these docs | Shown in your workspace |
    | --- | --- |
    | Initiative | **Engagement** |
    | Program | **Retainer** |
    | Project | Project |
    | Task | Task |
    | Cycle | **Sprint** |
    | Team | **Pod** |
  </Tab>
</Tabs>

`Project` and `Task` read the same across every sector, so they are the same word in all three
presets. If you only ever meet those two, the preset makes no visible difference.

## Per-word overrides

A workspace can also override any single word on top of its preset. A nonprofit running the
Nonprofit preset can still rename `Program` to `Service` and leave everything else alone, so
the words on your screen may not match any preset exactly.

Set the preset and any overrides in **Settings → General → Terminology**. In a shared workspace
that is an admin setting, so the whole workspace reads the same words.

## What terminology does not change

Changing the preset changes labels. It leaves everything else where it was:

- No work is moved, renamed, or re-parented.
- Every rule in [Core concepts](/guides/concepts/workspaces) still holds — a Cycle called a
  Sprint is still team-scoped, still a fixed window of time, still schedules Tasks rather than
  containing them.
- The API, the MCP tools, and the [REST reference](/developers/rest-api) always use the
  default words. `project`, `cycle`, and `initiative` are the field names regardless of what
  your workspace displays.

That last point is the practical one: if you are reading these docs beside the API, the API
agrees with the docs. If you are reading these docs beside the app, translate through the table
above.

<Note>
  Terminology is set per workspace, so each of yours can differ. Your personal space keeps its own
  setting under the same **Settings → General**, and starts on the default words.
</Note>
