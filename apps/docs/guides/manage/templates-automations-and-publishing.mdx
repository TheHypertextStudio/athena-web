title: 'Templates, automations, and publishing'
description: 'Reuse a starting point, run repeatable rules, and publish a read-only brief.'
---

These settings change what Docket creates or exposes. Open them inside the workspace they should
affect.

## Reuse a starting point

Open **Settings → Templates** to create reusable Tasks, Projects, Initiatives, and Programs. A
template can belong to you, one Team, or the whole workspace.

Choose **Start from template** when you create matching work. Docket merges the template into the
creation form so you can change the result before saving it. A template does not keep controlling
work after creation.

Cycles and Teams do not use templates.

## Run an automation

Open **Settings → Automations** to create rules for task events and email suggestions. Each rule
shows its trigger, conditions, and actions. Keep the rule narrow enough that someone can explain why
it ran from those three parts.

Disable a rule before changing a live workflow that depends on it. Existing work stays as it is;
the disabled rule only stops future runs.

## Publish a brief

Publish a Project when someone outside Docket needs a read-only status page. The brief can show the
Project's current public information without giving the visitor a Docket account.

An admin opens **Settings → Publishing** to manage the default workspace address and custom domains.
The Primary badge marks the address visitors should use. Changing an address does not change the
Project itself.

<Warning>
  Publishing is an access decision. Review the brief in a signed-out browser before sharing its
  address.
</Warning>
