# Design review: the OAuth consent screen (`/oauth/authorize`) — 2026-08-02

Screenshots: `docs/design/audits/screenshots/2026-08-02-oauth-authorize/` — 20 PNGs, plus the raw
runtime measurements in `probe.json` alongside them.

Every capture is of the **real signed request**, not a mock: a client was dynamically registered
against the running authorization server, and the browser (carrying the saved design-review session)
was driven through `/api/auth/oauth2/authorize` so the screen rendered from a genuine `sig`-bearing
query. Four states were captured at 1440×900 and 390×844 in both themes:

| File prefix                 | State                                                                                       |
| --------------------------- | ------------------------------------------------------------------------------------------- |
| `consent-realistic-*`       | `Claude` requesting all five permissions, returning to `claude.ai` — the production case    |
| `consent-all-scopes-*`      | The same request with the dev stack's own 48-character branch host — a wrapping stress case |
| `consent-unknown-scope-*`   | A request naming a permission Docket cannot grant                                           |
| `consent-session-pending-*` | `/api/auth/get-session` held open indefinitely                                              |
| `consent-expanded-*`        | Every disclosure open (1440×900, both themes)                                               |
| `consent-focus-*-zoom.png`  | Keyboard focus on the first and last permission rows, cropped                               |

This surface is the one place a person decides whether to trust an outside application with their
work, so it is reviewed against a stricter question than the rubric alone: **is every sentence on it
true, and would someone who has never heard of an authorization server understand it?**

## Findings

Resolved in this pass:

1. **The keyboard focus ring was three-quarters invisible.** — `apps/web/src/app/(auth)/oauth/authorize/page.tsx` — The permission rows carried the standalone `focus-visible:ring-2`, but the list is a scroll container (`max-h-[45dvh] overflow-y-auto`), which clips anything drawn outside a child's box. On the first and last rows only one edge survived, and a lone blue line under a row reads as a divider, not as focus. Replaced with the design system's `focusRingInset`, which exists for exactly this case. Before/after evidence: `consent-focus-first-row-zoom.png`, `consent-focus-last-row-zoom.png`.
2. **A raw permission identifier could reach the screen.** — `page.tsx` previously resolved a row as `info?.label ?? scope`, so an unrecognized request rendered as `some:future` in front of someone with no way to know what that meant. Every row now resolves through `describeScope()` in `apps/web/src/lib/oauth-scope-copy.ts`, which has no branch that can echo its input, and the row says plainly that approving it grants nothing — true, because the authorization server's issuable set is closed.
3. **The screen threw away everything it already knew.** — Pending and unreachable session reads rendered a bare `Loading…` paragraph. Who is asking, what they are asking for, and where you will be returned all come from the URL and are knowable on the first paint; only the account address and the decision itself need the session.
4. **Nothing said what the two buttons do.** — Two bare verbs asked a reader to guess whether Deny cancels the connection or the whole sign-in, and whether Authorize is permanent. One application-owned sentence pair above the button row now names the app and the return host.

Open, both minor and non-blocking:

5. **The capped list has no scroll affordance.** — `page.tsx` — With every disclosure expanded the `45dvh` cap cuts the last visible row mid-row with nothing indicating more is below (`consent-expanded-1440x900-light.png`). The list is scrollable and the default collapsed five-permission request never reaches the cap, so nobody is stuck — but a top/bottom mask would make the affordance legible rather than inferable.
6. **A very long return host pushes Deny just past the fold on a phone.** — At 390×844 with the dev stack's 48-character branch host, `Deny` ends at 859px against an 844px viewport; with a realistic host (`claude.ai`) it ends at 843px and both buttons are fully visible without scrolling (`probe.json`, `realisticMobile` vs `longHostMobile`). This is ordinary document scroll, not clipping, and the primary action is above the fold in both cases.

Verdict: **SHIP** — every dimension is at least 3 and all five gates pass.
