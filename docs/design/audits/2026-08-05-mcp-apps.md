# Design review: MCP App widgets — 2026-08-11

Screenshots: `docs/design/audits/screenshots/mcp-apps/` — 216 captures. Twenty-seven cases across
sixteen widgets, each at 720px and 320px, in light and dark, both with a host-supplied palette and
with none. Captured by `apps/web/e2e/mcp/widget-shots.spec.ts`, which drives the real SEP-1865
handshake against a controlled host rather than screenshotting a mock. A live third-party-host
capture remains a release check; this audit records the shipping widget contract, not a claim about
an external host's chrome.

## What this surface is

Sixteen `ui://` documents that render inside someone else's product. A host serves them under a
deny-all CSP in an opaque origin and talks to them only over `postMessage`, so nothing about their
appearance is reachable from a unit test and nothing about their styling can be imported from
`@docket/ui`. The register is the app one — calm, MD3 tonal, Plex where Plex can reach, which here
it cannot.

## Semantic entity views

The legacy `get` resource remains callable for direct integrations, but is app-only in tool
metadata so model discovery leads with explicit `get_tasks`, `get_projects`, and the ten other
same-type reads. Each returns server-owned `href` values: a widget never guesses whether an entity
is a task. One result receives a semantic detail card; a batch is deliberately a plain row list
with one correctly labelled "Open in Docket" action per item. The Bus Buddies three-project case
proves that every requested row renders and that a missing reference stays a quiet note. Only the
single task document exposes state and due-date controls.

## The starting point

This review was triggered by a screenshot of a live `update` call: a card in browser-default serif,
with no background fill, whose content overflowed the frame and was clipped mid-sentence, beside a
second card stuck on the word "Working…". Three independent causes, none of which could fail loudly.

## Findings still open

1. **Plex cannot reach a widget.** The frame is an opaque origin under `font-src 'self'`, so the
   app's `@font-face` is unreachable and the card lands on the same system sans the app falls back
   to. Closing it means widening the CSP and serving the woff2 from the API origin. Deliberately
   deferred: inside Claude the host's font is the correct choice anyway, and this only costs
   Docket's own Athena panel.
2. **The work list cannot be edited.** A row carries its state key but not its team's workflow, and
   one list can span every team in the org, so there is no way to know what "done" is called for
   any given row. The entity card is where that edit lives. Fixing it would mean shipping every
   team's workflow with every page.
3. **The design-policy tests this scorecard is written for still do not exist.** Not a new finding
   — GEN-10's own evidence in `launch-compliance.json` already records that
   `scripts/surface-inventory.ts`, `surface-inventory.test.ts` and `scorecard-schema.test.ts` were
   present in a working tree but never tracked by git. Confirmed still true: `git log --all` on all
   three paths is empty. So this header is unvalidated, `surface-inventory.md` is now maintained by
   hand, and the four widget rows added to it are a claim rather than a generated fact.
4. **`prefersBorder` is declared but unverified.** Docket's own host reads it. Whether Claude does
   is unknown; it costs one line and is harmless if ignored.
5. **The fullscreen overlay is not a fully trapped modal.** It carries `role="dialog"`,
   `aria-modal`, an accessible name, an autofocused Close control and Escape-to-close — enough that
   expanding is announced and always has a visible exit. It does not yet confine Tab: nothing marks
   the page behind it inert, so a determined keyboard user can still reach the obscured content.
   The a11y gate above is recorded as passing on the strength of the announce-and-exit behaviour;
   the containment gap is real and is the next thing to close on this surface.
