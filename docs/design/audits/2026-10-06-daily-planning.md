# Design review: daily planning — October 6, 2026

This review is for Docket's product and engineering maintainers. Use it to check the daily loop before deployment. The screenshots use an authenticated local fixture account. They are visual evidence, not production acceptance.

The application uses Docket's Plex typography and shared MD3 surfaces. Today remains home. Daily planning now occupies a separate activity route and centered workspace without the application sidebar, workspace header, document tabs, or side panels. The date, contained stage buttons, and Today exit provide its navigation. Today and weekly planning retain the application shell. Review yesterday, Plan today, Review plan, and confirmation each retain their own screen. Add work opens a separate searchable surface. The October 7 activity correction puts the agenda first during review and keeps selected work in a second panel. The Panels menu can show Work, Agenda, or both. Hiding a panel preserves its mounted controls and edits. The shared workspace header and action footer remain outside the scrolling content. Secondary task actions open only when requested. Workday settings stay collapsed during review, except when a missing saved schedule requires the person to choose bounds. All-day context sits above the timed canvas instead of occupying a full-day rectangle.

The capture set is in [screenshots/2026-10-06-daily-planning](screenshots/2026-10-06-daily-planning/). Every main stage has 1440 × 900 desktop, 390 × 844 phone, 320 × 844 narrow phone, and 390 × 600 short phone captures in both themes. The revision-preview set shows the proposed displacement before Apply. The revision set shows the updated-plan confirmation. The short-block set verifies five-minute geometry in planning, review, and Today.

The screenshots show no horizontal overflow at 320 pixels. The fixed workspace footer reserves its own space instead of covering the agenda. Review plan and Confirm plan remain visible while the content scrolls. Timed rectangles use the same minute scale for tasks and events. Short block details appear outside the timed rectangle when necessary.

The capture set includes an Agenda-only workspace at all four sizes in both themes. The full flow uses thirteen capture stages. A user enters planning from Today, opens Add work or a task composer within the activity, returns to the draft, reviews it, and confirms it. Returning to Today restores the application shell. The legacy daily URL redirects to the activity while retaining its date and recovery choice.

The first built activity run found two navigation errors. Resume planning used the workspace's offline link policy, and recovery read Today's address before the router committed the planning destination. Activity links now use the router without prefetching. The activity location reader uses the router destination online and the browser address during offline replay. A regression test failed before the correction and passes after it.
