## Product-journey findings

The four prior blockers are closed in the reviewed evidence:

1. **Returning to Event:** the actual work name and Continue defining Event action
   now lead its content. Included work is summarized separately from its purpose;
   Vendor booking has its own linked prerequisite relation and review action.
   The page no longer presents the work as settings rows with concatenated metadata.
2. **Publication order:** Event's review explains Publish Vendor booking before
   Event beside the publication decision. Publish is disabled while that known
   prerequisite exists. Vendor review offers Back to parent definition. Actual
   browser execution publishes Vendor, returns to Event and then publishes Event.
   Long starting documents are disclosed; included work appears first on phone.
3. **One definition, two states:** Community dinner says Unpublished changes ·
   Version 1 stays available, with its actual publication inside View published
   version 1. The draft and publication no longer appear as two independent rows.
4. **First use versus return:** the overview prioritizes unfinished definitions
   when present. A compact Define another kind entry stays near Continue defining;
   a subordinate start section distinguishes defining work from adapting an
   existing definition. Without custom drafts the start choice precedes ready
   definitions. Maintenance remains subordinate. The current workspace destination
   is visible and selected, with no Settings modal or All settings trail.
