# Changelog

## 0.4.0

- Add `work-on` for default alignment with existing tasks/projects and explicit user exceptions.
- Define task, project, initiative, and program agent responsibilities and explain the changed
  behavior during onboarding.
- Add shared references for agent assignments and subagent handoffs, permissions, dependencies,
  concurrent changes, reporting ownership, and combined acceptance.
- Move detailed recovery and monitoring procedures out of the recovery skill entrypoint.

## 0.3.0

- Define the Docket Workflow: define the outcome, choose the next work, do it, verify the result,
  and update the plan. Apply the same practices across personal, team, and agent work with flexible
  structure and cadence.
- Shorten onboarding to an entrypoint and move the method and conditional adoption procedures into
  focused reference documents.

## 0.2.2

- State onboarding instructions in concrete verbs: plan work, start agents from tasks, and record
  results on those tasks. Align the heading and listing copy with those actions.

## 0.2.1

- Lead onboarding with Docket's recommended operating loop: capture commitments, assign work from
  task references, verify acceptance, and return outcomes to the same records.
- Replace conditional menus with concrete defaults and a clear adoption decision. Recommend saving
  development conventions in repository guidance while preserving explicit constraints and authority.

## 0.2.0

- Add collaborative onboarding that reviews the person's broader workflow, explains relevant Docket
  best practices and tradeoffs, and lets them choose changes before trying the agreed loop on real work.
- Point Codex setup to `onboard`; retain `connect` for focused access troubleshooting in both hosts.
- Adapt first use to new, existing, returning, and blocked users without creating sample work,
  forcing integrations, or repeating completed setup.

- Distinguish missing calendar coverage from an empty schedule when planning daily work.

## 0.1.1

- Re-anchor `get-back-on-track` in the assigned Docket task or project, its scope, dependencies,
  current state, and acceptance criteria; relate resumed work and its outcome to the same record.
- Make unavailable or unrefreshed Docket context explicit without inventing replacement work.
- Complete OpenAI and Anthropic publisher, listing, support, policy, capability, and branding metadata.
- Add existing Docket artwork, MCP review cases, commerce disclosure, and release information.

## 0.1.0

- Bundle the remote OAuth MCP connection with seven shared work-management skills.
- Add local marketplaces for Codex and Claude Code and opt-in behavioral evaluation scenarios.
