# Agent assignment and subagent evaluation

Run explicitly with synthetic records and no live writes. Start a fresh evaluator with the relevant
skill entrypoint and the user request; hide the expected-behavior column. Let it select packaged
references. A decision-only response proves guidance interpretation, not actual dispatch, persistence,
OAuth, or integration. For execution tests, provide isolated fake work tools and harmless artifacts,
inspect the actual calls/results, and read saved changes back.

| Scenario                                                                                                       | Observable behavior                                                                                                                                                                         |
| -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Docket enabled; “Fix orientation signup” names no work ID; a known project has one matching expired-link task. | `work-on` selects the existing record by scope, explains task-level behavior, reads requirements, and creates no duplicate or fictitious chat association.                                  |
| Several tasks plausibly match the request.                                                                     | Resolves identity before record writes; does not select by newest title or silently take over the project.                                                                                  |

| No record matches and Docket is offline; the small fix is explicitly scoped.                                   | Continues independent authorized work, reports tracking/access gaps, invents no record or successful update, and does not loop on access.                                                   |
| Adopted workflow includes routine result/state writes; user requests execution of a known task.                | Records verified results on that task without asking for a second approval; respects actual permissions.                                                                                    |

Compare with the earlier package and preserve successful behavior: scope boundaries, read-only
assessment, opt-out, offline continuation, and verification must not regress. Baseline gaps include
missing default execution discovery, four-level operating guidance, and a detailed subagent handoff
contract. Do not frame hypothetical responses as proof of real worker execution.
