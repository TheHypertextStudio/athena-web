# Work from Docket

Try to align substantive execution with an existing Docket task or project. Reuse the known work
reference; resolve a relevant task under the project when needed. Honor an explicit user exception.
Ordinary questions do not require records, and missing access does not block independently scoped work.

Read [Agent assignments](../../references/agent-work.md) for matching, assignment levels, reporting
rights, and missing-record/access cases. Read [Working in Docket](../../references/work-management.md)
before work tools. Read [Subagents](../../references/subagents.md) only when coordinating workers.

1. Identify the work reference and the responsibility actually assigned: task execution, project
   coordination, initiative assessment/stewardship, or program operation. Explain the chosen record,
   intended result, verification, and reporting behavior when establishing or changing the assignment.
2. Read its scope and relevant dependencies. Execute the next action within that responsibility and
   current authority. Use `plan-work` for shaping work, `capture-work` for authorized missing tasks,
   and `get-back-on-track` when activity drifts from the assignment.
3. Verify the requested deliverable at its assigned level. Record authorized results on the original
   records through `update-work`; otherwise report them in conversation with the work reference and
   the explicit tracking gap. Reconcile current state before writing.

Parent context informs decisions; it does not enlarge authority. Do not invent hierarchy, persist
chat associations the host has not saved, or claim a project succeeded merely because its tasks did.
Keep detailed execution evidence in linked artifacts and descriptions useful for the next execution.
